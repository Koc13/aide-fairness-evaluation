# Experiments Documentation

This document describes the structure and organization of AIDE-ML experiments conducted for testing fairness across 10 different use cases.

## Overview

Experiments are organized in the `experiments/` directory with two main subdirectories:
- **`experiments/logs/`**: Contains AIDE-ML execution logs, configurations, and generated solutions
- **`experiments/workspaces/`**: Contains the working directories where AIDE-ML executed experiments, including input data and output predictions

**Examples:**
- `1-income-baseline`: Baseline income prediction with no fairness considerations
- `1-income-fairness-prompt`: Income prediction with fairness prompt
- `2-student-admission-baseline`: Student admission baseline
- `3-image-generation-fair-1`: Image generation fairness variant 1

## Directory Structure

### `experiments/logs/<experiment-name>/`

Each experiment log directory contains the following files:

| File | Description |
|------|-------------|
| `config.yaml` | AIDE-ML configuration including goal, evaluation metric, data paths, and model settings |
| `best_solution.py` | The best ML pipeline solution generated by AIDE-ML |
| `journal.json` | Execution journal tracking all iterations and attempts |
| `tree_plot.html` | Visual representation of the AIDE-ML search tree (when available) |
| `report.md` | Generated report analyzing the solution (when available) |
| `__pycache__/` | Python cache directory (when solution was executed) |

**Key configuration fields in `config.yaml`:**
- `goal`: The prediction task (e.g., "Predict PINCP" or "Predict PINCP while minimizing demographic parity difference")
- `eval`: Evaluation metric (e.g., "accuracy")
- `data_dir`: Path to input dataset
- `agent.steps`: Number of AIDE-ML iteration steps (typically 20)
- `agent.k_fold_validation`: Cross-validation folds (typically 5)

### `experiments/workspaces/<experiment-name>/`

Each workspace directory contains:

| Directory/File | Description |
|----------------|-------------|
| `input/` | Copy of the input dataset used for the experiment |
| `working/` | Working directory containing generated files |
| `working/submission.csv` | Final predictions/results generated by the best solution |

This file contains the complete ML pipeline generated by AIDE-ML, including:
- Data preprocessing steps
- Feature engineering
- Model training code
- Fairness interventions (if applicable)

### 3. Check Results
```bash
cat experiments/workspaces/<experiment-name>/working/submission.csv
```

Contains the final predictions generated by the best solution.

### 4. Review Search Process
Open `experiments/logs/<experiment-name>/tree_plot.html` in a browser to visualize:
- How AIDE-ML explored different solutions
- Which branches were successful
- The evolution of solution quality

### 5. Read Generated Report
```bash
cat experiments/logs/<experiment-name>/report.md
```

AIDE-ML generated analysis and insights (when available).

## Experiment Execution Flow

1. **Configuration**: Define task in `config.yaml` with goal, data, and settings
2. **Execution**: AIDE-ML runs iterative search (typically 20 steps)
3. **Logging**: All attempts recorded in `journal.json`
4. **Selection**: Best solution saved to `best_solution.py`
5. **Evaluation**: Solution executed in workspace, results saved to `working/submission.csv`
6. **Analysis**: Tree plot and report generated for review

## Result Logging and Traceability

Each experiment generates structured outputs that document both predictive performance and fairness characteristics.

Metrics files store overall scores group level scores and fairness gap values.

Configuration files record random seeds data split identifiers model settings and fairness related hyperparameters.

Prediction files store instance identifiers ground truth labels predicted labels and associated group attributes.

All summary tables and visualizations are generated directly from these stored outputs to ensure consistency between reported results and underlying experimental runs.

Through this strictly controlled experimental design, the four use cases provide a structured environment for analyzing how prompt driven methodological adjustments influence the balance between predictive accuracy and fairness under identical data conditions.
